# PersonalAIOS 技术架构（初稿）

> 文档状态：初稿（项目初始化阶段，尚未进入方案评审）
> 最后更新：2026-11-20
> 重要说明：本文档中的技术选型均为**初步候选**，未经确认，不得直接作为实现依据。所有未确认项标注「待确认」。

## 1. 技术选型原则

1. 个人项目优先，控制复杂度，避免过早引入分布式组件。
2. 数据本地可读、可迁移，避免强绑定单一云服务。
3. 选型需可回退：关键依赖（数据库、模型供应商）应可通过适配层替换。
4. 优先选择社区成熟、文档完善的方案。
5. 任何选型在确认前只做记录，不安装依赖、不写实现。

## 3. 系统整体架构（逻辑分层）

当前仅为逻辑分层草案，物理部署形态待确认。

```text
┌─────────────────────────────────────────────┐
│  交互层（界面 / CLI / 接口）                 │  ← 形态待确认
├─────────────────────────────────────────────┤
│  应用服务层（用例编排、权限与校验）           │
├─────────────────────────────────────────────┤
│  业务模块层（任务 / 资料 / 知识库 …）         │  ← 模块待确认
├─────────────────────────────────────────────┤
│  AI 能力层（模型调用、提示词、检索增强）       │  ← 方案待确认
├─────────────────────────────────────────────┤
│  数据访问层（仓储、索引、迁移）               │
├─────────────────────────────────────────────┤
│  存储层（结构化数据 / 文件 / 向量索引）        │
└─────────────────────────────────────────────┘
        横向能力：配置管理、日志、错误处理、可观测性
```

分层约束（建议，待确认）：

- 上层只能依赖下层，禁止反向依赖。
- 业务模块之间通过明确定义的接口交互，不直接访问彼此的数据表。
- AI 调用统一走 AI 能力层，业务模块不直接持有模型 SDK 客户端。

## 4. 模块关系

| 模块 | 依赖 | 被依赖 | 说明 |
| --- | --- | --- | --- |
| 交互层 | 应用服务层 | 无 | 用户入口 |
| 应用服务层 | 业务模块层、AI 能力层 | 交互层 | 用例编排 |
| 业务模块层 | 数据访问层、AI 能力层（可选） | 应用服务层 | 领域逻辑 |
| AI 能力层 | 数据访问层（检索时） | 应用服务层、业务模块层 | 模型与提示词封装 |
| 数据访问层 | 存储层 | 业务模块层、AI 能力层 | 读写与查询 |
| 存储层 | 无 | 数据访问层 | 实际持久化 |

> 待确认：模块清单需与 [project-plan.md](./project-plan.md) 的功能模块规划保持一致后再定稿。

## 5. 数据流转

以「用户发起一次请求」为例的初步流转：

```text
用户输入
  → 交互层接收并做基础校验
  → 应用服务层解析意图、编排用例
  → 业务模块层执行业务规则
  → （如需 AI）调用 AI 能力层
        → 组装上下文（必要时从数据访问层检索）
        → 调用模型，返回结构化结果
  → 结果经数据访问层持久化
  → 返回交互层展示
```

数据分类草案：

| 类别 | 内容 | 存储形式 | 状态 |
| --- | --- | --- | --- |
| 配置数据 | 用户偏好、密钥引用 | 本地配置文件 | 待确认 |
| 业务数据 | 任务、资料、笔记 | 结构化数据库 | 待确认 |
| 文件数据 | 附件、导入文档 | 本地目录 `data/` | 待确认 |
| 索引数据 | 全文索引、向量索引 | 可重建的派生数据 | 待确认 |
| 日志数据 | 运行日志、审计日志 | 滚动日志文件 | 待确认 |

> 待确认：数据模型细节、是否加密、备份与迁移策略、敏感信息（API Key）存放方式。

## 6. AI 接入方案（草案）

1. **接入位置**：所有模型调用收敛到 AI 能力层，业务模块只调用能力层暴露的接口。
2. **供应商适配**：定义统一的模型调用接口（如：对话、摘要、嵌入），通过适配器对接具体供应商，便于替换。
3. **配置方式**：模型供应商、模型名称、API Key 通过配置项注入，密钥不得写入代码或提交到仓库（见 `.gitignore`）。
4. **上下文构建**：优先采用「检索后拼接上下文」的方式，避免一次性投喂全量数据。
5. **成本与限流**：需要本地记录调用量、设置超时与重试上限，具体阈值待确认。
6. **结果可解释**：AI 生成结果应标注来源（引用到的资料），便于人工核验。

> 待确认：供应商选型、是否支持本地模型、是否使用向量检索、提示词版本管理方式、失败降级策略。

## 7. 架构层面的待确认事项

1. 运行形态：Web 应用 / 桌面应用 / CLI / 本地常驻服务。

6. 日志与可观测性范围。
