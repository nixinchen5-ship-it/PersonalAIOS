# PersonalAIOS 技术架构（初稿）

> 文档状态：第二版（业务模块调整为五个）
> 最后更新：2026-11-20
> 重要说明：本文档中的技术选型均为**初步候选**，未经确认，不得直接作为实现依据。所有未确认项标注「待确认」。

## 1. 技术选型原则

1. 个人项目优先，控制复杂度，避免过早引入分布式组件。
2. 数据本地可读、可迁移，避免强绑定单一云服务。
3. 选型需可回退：关键依赖（数据库、模型供应商）应可通过适配层替换。
4. 优先选择社区成熟、文档完善的方案。
5. 任何选型在确认前只做记录，不安装依赖、不写实现。
6. 合并后的业务模块，其内部子能力通过模块内接口隔离，保留未来独立拆分的可能。

## 3. 系统整体架构（六层）

保持六层逻辑架构不变，仅将业务模块层替换为五个业务模块；调度、通知等作为横向能力存在，不新增层级。

```text
┌──────────────────────────────────────────────┐
│  交互层（桌面入口：悬浮球 / 快速对话 / 通知中心）│
├──────────────────────────────────────────────┤
│  应用服务层（用例编排、权限与校验、任务调度）   │
├──────────────────────────────────────────────┤
│  业务模块层                                    │
│  B1 个人知识库与长期记忆                       │
│  B2 个人发展与行动管理                         │
│  B3 情报与机会中心                             │
│  B4 扩展管理                                   │
│  B5 系统管理                                   │
├──────────────────────────────────────────────┤
│  AI 能力层（对话、摘要、嵌入、结构化抽取）      │
├──────────────────────────────────────────────┤
│  数据访问层（仓储、索引、迁移）                 │
├──────────────────────────────────────────────┤
│  存储层（结构化数据 / 文件 / 向量索引）          │
└──────────────────────────────────────────────┘
  横向能力：配置管理、日志与审计、任务调度与触发、通知分发、备份恢复
```

分层约束：

- 上层只能依赖下层，禁止反向依赖。
- 业务模块之间通过明确定义的接口交互，不直接访问彼此的数据表。
- AI 调用统一走 AI 能力层，业务模块不直接持有模型 SDK 客户端。
- 合并模块内部的子能力通过模块内接口协作，不跨模块直接调用。
- 扩展管理提供的外部能力必须显式声明所需数据范围与权限。

## 4. 模块关系

### 4.1 业务模块依赖

| 模块 | 依赖 | 被依赖 | 说明 |
| --- | --- | --- | --- |
| B1 个人知识库与长期记忆 | 数据访问层、AI 能力层（嵌入与抽取） | B2、B3 | 提供个人上下文服务 |
| B2 个人发展与行动管理 | B1（仅通过上下文接口）、AI 能力层 | 应用服务层 | 规划、行动与成长记录 |
| B3 情报与机会中心 | B1（仅通过上下文接口）、AI 能力层 | 应用服务层 | 外部信息分析与机会匹配 |
| B4 扩展管理 | 数据访问层 | B2、B3（可选） | 提供外部工具与服务扩展 |
| B5 系统管理 | 数据访问层 | 全系统（基础设施） | 配置、安全、备份、运行状态 |

### 4.2 合并模块的内部子能力

子能力先以模块内部服务形式实现，接口稳定后再考虑独立拆分。

| 模块 | 内部子能力 | 未来可独立拆分 |
| --- | --- | --- |
| B2 个人发展与行动管理 | 状态理解、目标管理、计划管理、任务追踪、提醒与建议、成长记录、阶段复盘、AI 对话 | 对话服务、提醒调度 |
| B3 情报与机会中心 | 信息采集、清洗去重、分类摘要、个性化筛选、机会匹配、简报生成 | 采集器、匹配引擎 |
| B1 个人知识库与长期记忆 | 资料管理、长期记忆、检索、来源追溯、上下文服务 | 检索服务、记忆服务 |

说明：B3 内部按「新闻子域」与「机会子域」分别定义数据模型、筛选规则与展示方式，仅共用采集、去重、调度、提醒等基础能力。

### 4.3 依赖约束

1. 禁止 B2 与 B3 之间直接依赖，共享数据统一以 B1 为来源。
2. 禁止任何模块绕过 AI 能力层直接调用模型。
3. B4 的扩展能力为可选项，核心流程不得依赖某个具体扩展。
4. B5 只提供基础设施能力，不包含业务判断逻辑。

## 5. 数据流转

### 5.1 用户对话请求

```text
用户输入
  → 交互层（桌面入口）接收并做基础校验
  → 应用服务层解析意图、编排用例
  → 业务模块层执行业务规则（对话由 B2 承载）
  → 调用 B1 的上下文服务，按需检索个人记忆与资料
  → 调用 AI 能力层，组装上下文并获取结果
  → 识别到新的事实候选时，写入「待确认」状态
  → 结果经数据访问层持久化
  → 返回交互层展示，并标注引用来源
```

### 5.2 定时任务（提醒与简报）

```text
调度触发（定时 / 条件）
  → 应用服务层分派任务
  → B2：生成提醒或建议
  → B3：执行采集、去重、筛选、匹配并生成简报
  → 通知分发（受频次与免打扰规则约束）
  → 交互层通知中心展示
```

### 5.3 外部信息采集（B3）

```text
外部来源
  → 采集器拉取原始条目
  → 清洗、去重、分类、摘要
  → 结合 B1 的个人画像做相关性判断与机会匹配
  → 写入结构化条目，保留来源与抓取时间
  → 按需进入简报或提醒
```

### 5.4 记忆写入与事实确认

```text
用户明示 / 资料抽取 / AI 推断
  → 生成事实候选，附带来源、时间与置信度
  → 状态标记：AI 推断 = 待确认
  → 用户确认 → 转为确定事实
  → 用户否认 → 标记失效，保留审计记录
  → 确定事实可被 B2、B3 作为上下文使用
```

### 5.5 数据分类草案

| 类别 | 内容 | 存储形式 | 状态 |
| --- | --- | --- | --- |
| 配置数据 | 用户偏好、模型设置、密钥引用 | 本地配置文件 | 待确认 |
| 个人资料与文档 | 简历、笔记、附件 | 结构化库 + 本地文件 | 待确认 |
| 记忆数据 | 事实、偏好、经历，含来源与确认状态 | 结构化库 | 待确认 |
| 任务与计划数据 | 目标、计划、任务、进度 | 结构化库 | 待确认 |
| 情报与机会条目 | 新闻条目、机会条目（分类存储） | 结构化库 | 待确认 |
| 索引数据 | 全文索引、向量索引 | 可重建的派生数据 | 待确认 |
| 日志与审计数据 | 运行日志、事实变更记录、扩展调用记录 | 滚动日志 / 结构化表 | 待确认 |

> 待确认：数据模型细节、是否加密、备份与迁移策略、个人数据是否允许发送至云端模型、API Key 存放方式。

## 6. AI 接入方案（草案）

1. **接入位置**：所有模型调用收敛到 AI 能力层，业务模块只调用能力层暴露的接口。
2. **能力抽象**：至少抽象对话、摘要、嵌入、结构化抽取四类能力，各自定义统一接口，便于替换供应商。
3. **供应商适配**：通过适配器对接具体供应商，支持后续切换云端模型或本地模型。
4. **配置方式**：模型供应商、模型名称、API Key 通过配置项注入；密钥不得写入代码或提交到仓库（见 `.gitignore`）。
5. **上下文构建**：优先采用「检索后拼接上下文」的方式，通过 B1 的上下文服务按需取用，避免投喂全量数据。
6. **事实抽取与确认**：AI 从对话或资料中抽取的个人事实默认标记为「待确认」，经用户确认后才进入确定记忆；未经确认的事实不得当作确定事实使用。
7. **成本与限流**：本地记录调用量与费用，设置超时、重试与预算上限，具体阈值待确认。
8. **结果可解释**：AI 生成结果应标注引用的资料与来源，便于人工核验。
9. **失败降级**：模型不可用时的降级策略待确认（如仅本地检索、排队重试）。

> 待确认：供应商选型、是否支持本地模型、是否使用向量检索、提示词版本管理方式、失败降级策略。

3. 数据库与向量存储的具体方案。
4. B3 的数据来源、抓取方式与合规边界。

6. 备份格式、存储位置与恢复粒度。
7. 扩展接口与权限模型（初期仅预留）。
8. 测试策略与覆盖率要求。
9. 日志与可观测性范围。
