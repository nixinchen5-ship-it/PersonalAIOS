# PersonalAIOS 项目计划

> 文档状态：第二版（业务模块调整为五个）
> 最后更新：2026-11-20
> 说明：本文档已按项目实际定位与五模块划分调整。技术选型、外部数据源等未确认内容仍标注「待确认」，不得作为实现依据。

## 1. 项目背景

个人在长期学习与工作中积累的信息、经历、目标与偏好，通常分散在笔记、文档、聊天记录、待办工具和各类资讯平台之间：

- 通用聊天机器人缺少对个人的长期了解，每次对话都要重新交代背景。
- 任务与计划工具只管理待办，无法结合个人经历判断什么值得做。
- 资讯与招聘平台内容过载，无法按个人情况筛选，实际机会容易错过。

PersonalAIOS 是面向个人使用、长期运行的 Windows 桌面 AI 助理系统。它不是一次性的聊天工具，也不只是任务管理工具，而是通过持续积累个人上下文，在知识、行动和外部信息三个方向上提供持续性辅助。

## 2. 项目定位与边界

### 2.1 定位

- **单用户**：仅本人使用，不设计多用户与账号权限体系。
- **Windows 桌面**：以桌面常驻形态运行，提供悬浮球、快速对话、系统通知等入口（具体形态待确认）。
- **长期运行**：常驻后台、持续积累数据、持续演进，而非一次性会话工具。
- **以记忆为基础**：个人知识库与长期记忆是其余业务能力的前提。

### 2.2 当前阶段的非目标

- 不做团队协作、多用户与账号体系。
- 不做公开内容发布平台。
- 不做复杂插件市场与强隔离沙箱，初期只为扩展预留空间。
- 多设备同步不在当前定位内（是否作为远期目标待确认）。

## 3. 项目目标

| 编号 | 目标 | 说明 | 状态 |
| --- | --- | --- | --- |
| G1 | 建立可持续演进的项目骨架 | 文档、目录、规范先行 | 已完成（阶段 0） |
| G2 | 建立个人知识库与长期记忆 | 记录、检索、追溯、提供个人上下文 | 首版 MVP |
| G3 | 基于个人上下文提供对话与行动辅助 | 首版仅要求最小可用的 AI 对话 | 首版 MVP（最小范围） |
| G4 | 外部情报与机会的个性化筛选与提醒 | 采集、分析、匹配、简报 | 后续版本 |
| G5 | 个人数据可控、可追溯、可备份 | 用户拥有查看、修改、删除、导出权 | 持续要求 |

目标衡量方式（成功标准）暂未定义。

> 待确认：G2～G4 的量化指标（如检索命中率、简报打开率）。

## 4. 核心设计原则

1. 以个人知识库和长期记忆为基础。
2. 模块之间相对独立，通过明确接口共享必要的数据与能力。
3. AI 模型及外部服务尽可能可替换。
4. 重要数据可追溯、可备份、可恢复。
5. 用户拥有个人数据的管理权。
6. AI 推断出的个人事实，在未经确认前不能直接当成确定事实。
7. 主动通知保持克制，避免信息过载。
8. 新功能不能破坏已有功能。
9. 每个模块开发完成后都必须经过实际测试和验收。

## 5. 核心需求与 MVP 范围

### 5.1 首版 MVP（已确认）

首版只做三项核心能力，其余模块能力不进入首版验收范围。

| 能力 | 首版范围 | 归属模块 |
| --- | --- | --- |
| 个人知识库 | 个人信息记录、资料管理、基础检索、来源追溯 | B1 个人知识库与长期记忆 |
| 长期记忆 | 事实与偏好沉淀、个人上下文提供；AI 推断事实需经确认 | B1 个人知识库与长期记忆 |
| AI 对话 | 基于个人上下文的自然语言问答，最小可用 | B2 个人发展与行动管理（依赖 B1） |

### 5.2 后续需求

| 需求 | 归属模块 | 状态 |
| --- | --- | --- |
| 任务、计划、提醒 | B2 个人发展与行动管理 | 后续版本 |
| 目标管理与阶段复盘 | B2 个人发展与行动管理 | 后续版本 |
| 学习、技能与项目经历记录 | B2 个人发展与行动管理 | 后续版本 |
| 资讯采集、筛选与每日简报 | B3 情报与机会中心 | 后续版本 |
| 岗位与机会匹配提醒 | B3 情报与机会中心 | 后续版本 |

| 备份恢复、健康检查 | B5 系统管理 | 随 MVP 提供最小能力，待确认 |

## 6. 业务模块规划

### 6.1 模块总览

| 编号 | 模块 | 定位 | 首版是否包含 | 状态 |
| --- | --- | --- | --- | --- |
| B1 | 个人知识库与长期记忆 | 系统基础 | 是（核心） | 未开始 |
| B2 | 个人发展与行动管理 | 核心业务 | 部分（仅 AI 对话） | 未开始 |
| B3 | 情报与机会中心 | 核心业务 | 否（后续版本） | 未开始 |
| B4 | 扩展管理 | 支撑 | 否（仅预留扩展空间） | 未开始 |
| B5 | 系统管理 | 支撑 | 部分（配置与备份最小能力，待确认） | 未开始 |

### 6.2 各模块职责与子能力

#### B1 个人知识库与长期记忆

定位：整个系统的基础，负责个人信息记录、资料管理、长期记忆、信息检索、来源追溯和个人上下文提供。

子能力：

- 个人信息记录：个人资料、经历、偏好等结构化与非结构化信息。
- 资料管理：文档、笔记、附件的导入、归类与维护。
- 长期记忆：事实与偏好的沉淀、去重、更新与失效处理。
- 信息检索：关键词检索与语义检索。
- 来源追溯：每条记忆与资料可回溯到原始来源。
- 个人上下文提供：向 B2、B3 提供用户画像与相关上下文。

边界：不负责计划制定与行动推进（属 B2），不负责外部信息采集（属 B3）。

#### B2 个人发展与行动管理

定位：基于个人知识库和长期记忆，理解用户当前情况、目标和实际进度，帮助用户制定计划、推动行动、追踪成长并动态调整建议。

子能力：

- 当前状态记录与理解。
- 长期目标与阶段目标管理。
- 每日、每周、每月计划制定。
- 任务管理与执行进度追踪。
- 提醒与主动建议。
- 学习、技能、项目和实践经历记录。
- 个人能力变化追踪。
- 阶段复盘与成长报告。
- AI 对话（首版 MVP 的最小范围）。

边界：不直接存储外部资讯与机会（属 B3）；个人上下文不自行落库，统一来自 B1。

#### B3 情报与机会中心

定位：持续获取外部信息，结合用户个人情况进行筛选、分析和匹配，帮助用户发现值得关注的信息与实际机会。

子能力：

- 新闻、行业动态等信息采集。
- 实习、招聘、比赛、训练营、活动和城市资源采集。
- 信息清洗、去重、分类与摘要。
- 个性化信息筛选与分析。
- 结合个人知识库做相关性判断。
- 岗位与机会匹配。
- 定期简报与重要机会提醒。

说明：情报与机会中心是一个统一业务模块，但新闻信息与招聘机会在数据属性、筛选逻辑和展示方式上分别设计，不为了合并而强行统一；两者共用采集、去重、调度与提醒等基础能力。

#### B4 扩展管理

定位：负责外部工具、服务和插件的扩展管理。

子能力：

- 扩展点预留与注册。
- 外部工具与服务的接入配置。
- 扩展所需的数据范围与权限声明。

边界：初期只预留合理扩展空间，不开发复杂插件市场和沙箱。

#### B5 系统管理

定位：负责配置、模型设置、数据备份恢复、日志、安全和运行状态管理。

子能力：

- 配置管理。
- 模型与 AI 服务设置。
- 数据备份与恢复。
- 日志与审计记录。
- 安全与敏感信息管理。
- 运行状态与健康检查。

边界：不承载业务规则，只提供基础设施与系统级能力。

### 6.3 模块关系

- **B1** 提供用户画像、历史经历、偏好和个人资料，是 B2、B3 的共同输入。
- **B2** 利用个人记忆理解用户状态，规划和追踪个人发展。
- **B3** 利用个人记忆分析外部信息并匹配相关机会。
- **B4** 为其他模块提供外部工具与服务的扩展能力。
- **B5** 为整个系统提供配置、安全、数据管理和运行保障。

```text
                    ┌───────────────────────────────┐
                    │ B1 个人知识库与长期记忆（基础） │
                    │ 用户画像 · 经历 · 偏好 · 资料   │
                    └───────┬───────────────┬───────┘
              个人上下文接口│               │个人上下文接口
                    ┌───────▼───────┐ ┌─────▼───────────┐
                    │ B2 个人发展与 │ │ B3 情报与机会   │
                    │ 行动管理      │ │ 中心            │
                    └───────┬───────┘ └─────┬───────────┘
                            │ 外部能力调用   │
                    ┌───────▼───────────────▼───────┐
                    │ B4 扩展管理（外部工具与服务）   │
                    └───────────────────────────────┘

  B5 系统管理（配置 / 模型设置 / 安全 / 备份恢复 / 日志 / 运行状态）
  → 横向服务于 B1–B4，不参与业务逻辑
```

依赖约束：

1. B2、B3 不直接读写 B1 的数据表，只通过 B1 的「个人上下文服务」接口获取数据。
2. B2 与 B3 之间不直接依赖；需要共享的信息由 B1 提供或经应用服务层编排。
3. B4 的扩展调用必须显式声明所需数据范围。
4. B5 不承载业务规则，只提供基础设施能力。

## 8. 待确认事项

1. Windows 桌面技术路线与桌面壳方案。
2. AI 模型供应商，以及个人数据是否允许发送至云端模型。
3. B3 的信息来源范围与采集合规边界。
4. 主动通知策略（频次、免打扰时段、分级规则）。
5. B5 备份位置、备份粒度与恢复方式。
6. B4 插件开放程度（仅内部扩展 / 允许第三方）。
7. 长期记忆中 AI 推断事实的确认交互形态（即时确认 / 集中审阅）。
8. 多设备同步是否纳入远期目标。
9. 项目许可协议与开源 / 私有属性。
