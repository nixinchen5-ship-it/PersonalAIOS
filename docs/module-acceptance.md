## 3. 验收标准

### 3.1 通用验收标准（适用于所有模块）

1. 功能符合该模块需求说明，边界情况有明确处理。
2. 代码符合 [development-standards.md](./development-standards.md)。
3. 关键逻辑有对应测试，测试可重复执行且全部通过。
4. 无已知的阻塞性缺陷；非阻塞问题已登记到「问题记录」。
5. 不引入未确认的依赖或技术方案。
6. 文档同步更新，且与项目计划、技术架构保持一致。
7. 不包含敏感信息与临时文件。

### 3.2 数据类通用标准（适用于 B1、B3、B5）

为避免各模块重复定义，数据相关验收统一按本节执行：

1. 数据可追溯：每条记忆、情报与机会条目都可回溯到原始来源与时间。
2. 数据可管理：用户可查看、修改、删除、导出个人数据。
3. 数据可恢复：纳入备份范围的数据可完整恢复，且恢复后索引可重建。
4. 事实分级：AI 推断出的事实必须带「待确认」状态，未确认前不得作为确定事实展示或使用。
5. 删除一致性：删除来源数据后，由它派生的记忆与索引同步失效，并保留审计记录。

## 6. 验收流程

1. 开发完成 → 模块状态置为「待验收」。
2. 按第 3 节标准逐条自检，并在第 4 节登记测试记录。
3. 验收不通过时，问题登记到第 5 节，状态回退为「进行中」。
4. 验收通过后，模块状态置为「已通过」，并注明测试记录日期。
5. 合并模块（B2、B3）按子能力分别验收，全部子能力通过后才算模块通过。

## 7. 待确认事项

1. 各子能力专项验收标准的可执行判定条件。
2. 是否需要自动化测试覆盖率门槛。
3. 验收负责人与评审方式（个人项目是否自验收）。
4. 缺陷严重程度的最终分级口径。
5. B1 与 B2 之间记忆写入与确认流程的归属。
