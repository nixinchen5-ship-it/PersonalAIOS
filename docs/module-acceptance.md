## 3. 验收标准

### 3.1 通用验收标准（适用于所有模块）

1. 功能符合该模块需求说明，边界情况有明确处理。
2. 代码符合 [development-standards.md](./development-standards.md)。
3. 关键逻辑有对应测试，测试可重复执行且全部通过。
4. 无已知的阻塞性缺陷；非阻塞问题已登记到「问题记录」。
5. 不引入未确认的依赖或技术方案。
6. 文档同步更新，且与 [project-plan.md](./project-plan.md)、[technical-architecture.md](./technical-architecture.md) 保持一致。
7. 不包含敏感信息与临时文件。
8. 未新增未被确认的功能范围（不夹带需求）。

### 3.2 数据类通用标准（适用于 M2、M5、M6）

1. **可追溯**：每条记忆、情报与机会条目都能回溯到来源与时间。
2. **可管理**：用户可查看、修改、删除、导出个人数据。
3. **可恢复**：纳入备份范围的数据可完整恢复，恢复后索引可重建。
4. **事实分级**：AI 推断出的事实必须带「待确认」状态，未确认前不得作为确定事实展示或使用。
5. **删除一致**：删除来源数据后，由它派生的记忆与索引同步失效，并保留审计记录。

## 4. 首版模块专项验收标准

以下每条标准都必须可按步骤复现，验收时逐条记录「通过 / 不通过 / 阻塞」。

### 4.1 M1 基础底座

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| M1-01 | 项目可启动 | 按 README 命令安装并启动，页面/接口可访问，无报错 |
| M1-02 | 配置校验 | 删除必填配置项后启动，给出明确错误提示且不进入运行状态 |
| M1-03 | 配置更新 | 修改配置后无需改代码即可生效，非法值被拒绝 |
| M1-04 | 日志落盘 | 触发一次正常与一次异常操作，日志文件均生成，包含时间、级别、模块 |
| M1-05 | 统一错误处理 | 制造一次数据库异常，返回统一错误结构，不暴露堆栈给界面 |
| M1-06 | 数据库初始化 | 首次启动自动建库建表；迁移脚本重复执行不报错、不重复建表 |
| M1-07 | 数据访问 | 通过数据访问层完成一次增、查、改、删，结果正确 |
| M1-08 | AI 接口可替换 | 通过配置切换 mock 与真实适配器，业务代码无需修改 |
| M1-09 | AI 调用记录 | 每次调用记录模型、耗时、token 用量、成功/失败状态 |
| M1-10 | 密钥不落库 | API Key 不出现在数据库、日志与前端产物中（检索验证） |
| M1-11 | 基础备份与恢复 | 用户可手动触发一次备份；备份文件包含恢复应用所需的数据库数据；删除测试数据后可通过备份恢复；恢复后应用能正常启动，原有数据可正常读取 |

### 4.2 M2 个人知识库与长期记忆

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| M2-01 | 新增记忆 | 录入一条个人信息，列表与详情可见，状态标记为「用户提供」 |
| M2-02 | 查看记忆 | 详情展示内容、来源、创建时间、确认状态 |
| M2-03 | 修改记忆 | 修改内容后详情更新，保留修改时间；旧值可按记录追溯 |
| M2-04 | 删除记忆 | 删除后列表不再显示；用相同关键词检索，结果中不再出现 |
| M2-05 | 删除一致性 | 删除知识库原始资料后，由它派生的记忆标记失效，检索不再返回 |
| M2-06 | 事实分级 | AI 抽取的个人事实默认状态为「待确认」，不进入确定事实列表 |
| M2-07 | 确认流程 | 确认一条待确认事实后，状态变为「用户确认」，可被检索与上下文使用 |
| M2-08 | 否认流程 | 否认一条待确认事实后，状态变为失效，不被检索与上下文使用 |
| M2-09 | 来源追溯 | 任取一条记忆，可定位到来源资料或来源对话 |
| M2-10 | 资料导入 | 导入一份文档后可按内容检索到；原文件被删除后导入记录有明确状态 |
| M2-11 | 检索能力 | 关键词检索返回相关条目，空结果时返回明确的「无结果」而非报错 |
| M2-12 | 上下文接口 | 代码检查确认：其他模块只能通过上下文服务取数，无直接读 B1 数据表的调用 |
| M2-13 | 最小上下文 | 给定 50 条以上记忆，请求某主题上下文时只返回相关片段，且有数量上限 |
| M2-14 | 数据导出 | 导出的个人数据文件可被重新读取，字段完整 |
| M2-15 | 临时上下文不入长期记忆 | 在一次会话或任务中提供的临时信息（用户未明确要求记住），结束后检索不到对应长期记忆；用户明确要求记住时，才生成候选并按确认流程处理 |

### 4.3 M3 AI 对话

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| M3-01 | 基础对话 | 输入问题可获得回答，多轮对话上下文连贯 |
| M3-02 | 按需调用记忆 | 提问涉及个人信息时触发检索，回答包含来自记忆的内容 |
| M3-03 | 无关问题不检索 | 提问与个人无关时，调用记录显示未请求个人上下文 |
| M3-04 | 不发送全量数据 | 准备 100 条记忆，单次调用的发送片段数不超过配置上限，且不含无关条目 |
| M3-05 | 来源标注 | 使用个人资料作答时，回答中列出来源标识，可跳转到对应记忆或资料 |
| M3-06 | 敏感信息拦截 | 输入身份证号、银行卡号、密码等内容，模型调用载荷中不包含原文 |
| M3-07 | 密钥保护 | 前端打包产物、日志、Git 历史中检索不到 API Key |
| M3-08 | 失败处理 | 断网或模型报错时，界面给出明确失败提示，不返回空回答 |
| M3-09 | 不虚构事实 | 个人资料中不存在的信息，回答不得编造为确定事实；可提示「暂无相关记录」 |
| M3-10 | 事实候选 | 对话中出现的个人偏好生成「待确认」候选，未经确认不进入确定记忆 |
| M3-11 | 调用可查看 | 用户可查看本次回答使用了哪些个人片段（数据使用可见） |
| M3-12 | 对话记录 | 对话可回看，删除对话后其派生候选事实按规则处理 |
| M3-13 | 临时上下文边界 | 对话中的临时设定（如「这次先按方案 A」）不自动写入长期记忆；新会话中不作为确定事实引用；用户明确要求记住时才生成「待确认」候选 |

## 7. 验收流程

1. 开发完成 → 模块状态置为「待验收」。
2. 按第 3、4 节标准逐条自测，并在第 5 节登记测试记录（用例数、通过数、失败数）。
3. 任一条不通过 → 模块状态回退为「进行中」，问题登记到第 6 节。
4. 全部通过 → 状态置为「已通过」，注明验收日期与记录人。
5. 合并类模块（M2 涉及记忆与知识库、M4 涉及助理与成长）按子能力分别验收，全部子能力通过后才算模块通过。
6. 涉及共享数据结构变更的验收，必须补测受影响模块的相关用例。

4. 缺陷严重程度的最终分级口径。
